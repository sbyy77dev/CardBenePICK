# 실행 전 필요 설정

## 1. Gmail API 인증서 설정

1. Google Cloud Console 접속: Google 계정으로 Google Cloud Console에 로그인합니다.

2. 새 프로젝트 생성: 상단의 프로젝트 선택 드롭다운에서 '새 프로젝트'를 클릭하여 새로운 프로젝트를 만듭니다 (예: My Airflow Project).

3. Gmail API 활성화:

    - 좌측 메뉴에서 **'API 및 서비스' > '라이브러리'**로 이동합니다.

    - 검색창에 "Gmail API"를 검색하고 선택한 뒤, '사용 설정' 버튼을 클릭합니다.

4. OAuth 동의 화면 구성:

    - 좌측 메뉴에서 **'API 및 서비스' > 'OAuth 동의 화면'**으로 이동합니다.

    - **'User Type'**은 **'외부'**를 선택하고 '만들기'를 클릭합니다.

    - 앱 이름(예: Airflow Mailer), 사용자 지원 이메일, 개발자 연락처 정보만 입력하고 다른 항목은 비워둔 채 맨 아래로 스크롤하여 **'저장 후 계속'**을 누릅니다.

    - '범위' 단계는 그냥 '저장 후 계속'을 누릅니다.

    - '테스트 사용자' 단계에서 '+ ADD USERS' 버튼을 클릭하고, 사용자님의 Gmail 주소를 추가한 뒤 '저장 후 계속'을 누릅니다.

5. 사용자 인증 정보 만들기:
    - 좌측 메뉴에서 **'API 및 서비스' > '사용자 인증 정보'**로 이동합니다.

    - 상단의 **'+ 사용자 인증 정보 만들기' > 'OAuth 클라이언트 ID'**를 선택합니다.

    - **'애플리케이션 유형'**으로 **'데스크톱 앱'**을 선택합니다.

    - 이름을 입력하고 '만들기'를 클릭하면 클라이언트 ID가 생성됩니다.

    - 생성된 클라이언트 ID 목록에서 방금 만든 항목 오른쪽의 **다운로드 아이콘(JSON 다운로드)**을 클릭합니다.

6. 파일 이름 변경 및 이동:

    - 다운로드된 JSON 파일의 이름을 **credentials.json**으로 변경합니다.

    - 이 파일을 Airflow 프로젝트의 dags 폴더 또는 이전에 생성한 config 폴더 안으로 이동시킵니다. 

    - config 파일이 없다면 생성해서 json 파일을 추가합니다.
    
7. token.json 생성:

    - credientials.json 설정이 완료되었다면, generate_token.py를 실행하여 token.json 을 생성합니다.

    - confing 파일에 생성된 token.json 파일을 넣습니다.
    
## 2. MySQL 설정
- 현재 사용자의 정보를 얻기 위해 MySQL을 사용하고 있습니다

- 이용하기 위해서는 .env 파일에 MySQL 설정을 해야합니다.

```
MYSQL_SERVER="Your server IP or Address"
MYSQL_DB="Your Database Schema name"
MYSQL_USER="Your user name"
MYSQL_PASSWORD="Your user password"
```

## 크롤링
### 1. 속도 저하의 근본 원인: 
- I/O 바운드 작업원래 사용하시던 Selenium 코드가 느린 이유는 Selenium을 사용한 웹 크롤링이 대표적인 I/O 바운드(I/O-Bound) 작업이기 때문
- I/O 바운드: CPU 연산보다 입출력(I/O) 대기 시간이 훨씬 긴 작업을 의미
- Selenium의 I/O 작업 예시:
    - 브라우저 시작/종료 시간: Chrome 드라이버를 띄우고 끄는 데 걸리는 시간.
    - 페이지 로딩 대기: 웹사이트 서버에서 데이터를 받아와 브라우저가 화면을 그리는 대기 시간.
    - 명시적 대기: time.sleep(), WebDriverWait 등 서버 부하 조절 및 요소 로딩을 기다리는 시간.

기존 코드에서는 카드 1개를 처리하는 데 약 5초가 걸렸다면, 그 5초 중 대부분은 CPU 연산이 아닌 위의 **'대기 시간'**.

### 2. 빨라진 비결: 
- 병렬 처리 (ThreadPoolExecutor)새로 적용한 코드는 이 긴 '대기 시간'을 낭비하지 않고 다른 작업을 처리하는 병렬 처리 기법을 사용.

|구분 | 순차 처리(원래 코드) | 병렬 처리 (새 코드) |
|---|---|---|
|처리 방식| 카드 1개를 완전히 끝낸 후, 카드 2개 시작. | 최대 5개(MAX_WORKERS)의 카드를 동시에 시작.|
|대기 시간 활용| 카드 1번이 로딩을 기다리는 동안, 아무것도 안 함.| 카드 1번이 로딩을 기다리는 동안, 카드 2~5번이 로딩/클릭/데이터 추출을 진행함.|
|주요 도구|for 반복문, time.sleep()|ThreadPoolExecutor|
효율|N개의 카드가 있다면 N배의 시간이 걸림.|N개의 카드가 있어도 동시 처리 수(MAX_WORKERS)만큼 시간이 단축됨.|

#### 코드에서 바뀐 부분의 역할
1. ThreadPoolExecutor(max_workers=5) 도입:
- 병렬 처리의 엔진. 최대 5개의 독립적인 작업 공간(스레드)을 만들어서 동시에 명령을 수행하도록 지시.
2. process_single_card 함수:
- 이 함수는 하나의 카드를 처음부터 끝까지 처리하는 독립적인 단위.
- 이 함수가 실행될 때마다 개별적인 Selenium 드라이버가 생성되고 (driver = setup_driver()), 작업 후 바로 종료(driver.quit()).
- 이러한 격리된 환경 덕분에, 5개의 드라이버가 동시에 독립적으로 페이지를 로딩하고 클릭 가능

결론적으로, 카드를 한 줄로 세워놓고 순서대로 처리하는 것이 아니라, 5개의 창구(브라우저)를 만들어서 손님(카드 ID)을 동시에 처리했기 때문에 속도가 획기적으로 개선
